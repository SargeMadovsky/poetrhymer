# Poetrhymer — структура и план

Дата исходного плана: 15 ноября 2026. Обновлено 16 ноября 2026: создан прототип 0.1 на Rust с текстовым редактором, секциями, частичным импортом локального словаря Rhymes, фильтрами и заменой. Текущие возможности и ограничения описаны в [README](../README.md). План ниже описывает также последующие этапы, которые ещё не реализованы.

**Замысел и границы первой версии**

Локальный настольный редактор русскоязычных стихов и песен на Rust. Рабочее предположение: сначала Windows, затем другие настольные платформы. Текст, словарь и анализ доступны без сети. Основной сценарий: вставить текст → выбрать последнее слово строки → выбрать рифму к слову из другой строки → заменить слово, сохранив остальной текст.

Первый рабочий выпуск: редактирование, секции, большой локальный словарь, ручной выбор строки-пары, фильтры, замена и отмена. Следующий выпуск: автоматическое предложение рифмующихся пар и определение размера с ручной настройкой. Нейросетевая генерация, облачная синхронизация, совместное редактирование и музыкальные функции пока за пределами проекта.

**Интерфейс**

- Слева — компактное оглавление секций: куплеты, припевы, бриджи, произвольные названия.
- В центре — единый редактируемый текст с подсветкой заголовков и последних слов строк.
- Справа — панель рифм для выбранного слова: опорное слово, фильтры, результаты, предпросмотр строки.
- Внизу — анализ выбранной строки: слоги, ударения, предполагаемый размер и ручной переключатель.

Одиночный клик по последнему слову открывает панель и сохраняет обычную постановку курсора. Перетаскивание и двойной клик сохраняют выделение текста. Команда с клавиатуры вызывает тот же подбор для слова под курсором. В панели можно явно изменить опорное слово, не перемещая курсор в тексте.

Пример состояния панели:

```text
Заменить: фуража        Строка: 4
Рифма к: спеша          Из строки: 2 [Изменить]
Слоги: 3               Ударение: последний слог
Часть речи: любая       Качество: точные и близкие

Слово | ударение | слоги | часть речи | качество
…

Предпросмотр: «Заготовил …»
[Заменить]
```

Слоги заменяемого слова и его грамматика могут предлагаться как фильтры, но пользователь вправе их снять. Например, поиск ведётся по звучанию «спеша», а ограничение на три слога берётся из «фуража». Это две разные роли слов.

Замена выполняется только после выбора кандидата. Кавычки, точка, пробелы, переносы и регистр окружающего текста сохраняются. Одна замена — одно действие отмены. Подбор не обещает смысловой или грамматической уместности: пользователь видит будущую строку до применения.

**Разметка документа**

Заголовок распознаётся, если вся строка после удаления внешних пробелов заключена в квадратные скобки. Примеры: `[Куплет 1]`, `[Припев]`, `[Бридж]`, `[Verse 2]`, `[Chorus]`, `[Outro]`. Неизвестное имя создаёт пользовательскую секцию. Скобки внутри обычной строки заголовком не считаются; незакрытая скобка остаётся текстом.

Секция продолжается до следующего заголовка. Пустые строки разделяют строфы внутри секции. Текст до первого заголовка относится к безымянной секции. Одинаковые заголовки не означают связанные копии: каждый припев редактируется независимо. Заголовки исключаются из рифмовки и анализа размера.

Источник истины — исходный текст. Секции, строфы, токены и подсветка вычисляются поверх него. Разбор не переформатирует документ. Визуальный перенос длинной строки не создаёт новую стихотворную строку.

**Выбор рифмующейся пары**

В первом выпуске пользователь указывает строку-пару или вводит опорное слово вручную. Это позволяет сразу использовать любые схемы рифмовки.

Позже приложение предлагает связи по фонетическому сходству последних слов и положению строк внутри строфы. При наличии выбранной схемы учитываются AABB, ABAB, ABBA и произвольные группы, в том числе незарифмованные строки. Схема остаётся подсказкой: нельзя автоматически считать, что любые четыре строки рифмуются ABAB. Для исходного примера достаточно связи строк 2 и 4; строки 1 и 3 не требуется объявлять парой.

Ручная связь имеет приоритет. Опорой хранится ссылка на слово/строку, а не только копия текста, чтобы подбор обновлялся после правок. При удалении опорной строки связь сбрасывается явно. Для неоднозначного предложения панель показывает альтернативы; автоматическая замена не производится.

**Фильтры и сортировка**

В Rhymes описаны отбор и сортировка по качеству рифмы, количеству слогов, части речи, частотности и алфавиту; также есть обратная алфавитная сортировка. Это ориентир для нашего интерфейса, а не утверждение о полном воспроизведении программы. Источники: [главная страница](https://rifmovnik.ru/), [описание словаря](https://rifmovnik.ru/docs.htm).

| Возможность | Первый рабочий выпуск | Расширение |
|---|---|---|
| Качество | Точные / близкие, порог сходства | Настройка отдельных фонетических допусков |
| Слоги | Точное число или диапазон | Подсказка по ритму всей строки |
| Ударение | Положение ударения, число слогов после него | Несколько вариантов произношения |
| Часть речи | Выбор одной или нескольких | Падеж, число, род, время при наличии данных |
| Частотность | Сортировка, неизвестная частота показана явно | Отсечение редкой лексики |
| Формы слова | Группировка по лемме, раскрытие словоформ | Дополнительные настройки группировки |
| Повторы | Скрыть исходное слово | Скрыть использованные в секции слова |
| Порядок | Качество, частота, алфавит | Обратный алфавит |

Грамматические признаки — характеристики словоформы, а не гарантия согласования с предложением. Отсутствующие данные нельзя выдавать за отрицательное значение признака. Фильтр соответствия размеру включается только после появления модуля метрики.

**Словарь и поиск**

Нужен словарь словоформ с ударениями. Простого списка начальных форм или совпадающих буквенных окончаний недостаточно. Хранить все пары рифм не нужно: для каждой словоформы строятся фонетические ключи, по ним извлекаются кандидаты.

Минимальная запись: написание, нормализованная форма для поиска, лемма, часть речи, доступные грамматические признаки, число слогов, вариант ударения, фонетическое представление, частота при наличии и происхождение данных. Одна словоформа может иметь несколько ударений и грамматических разборов.

Кандидаты источников:

- [Koziev/NLP_Datasets](https://github.com/Koziev/NLP_Datasets): исследовать разделы Stress и WordformFrequencies как основу ударений и частот.
- [OpenRussian](https://github.com/Badestrand/russian-dictionary): исследовать морфологические данные и пригодность форм для объединения.
- В дальнейшем — дополнительные источники и пользовательские слова.

Эти источники пока не выбраны окончательно. После исследования добавленных локальных файлов приоритетный кандидат для пробного импорта — база Rhymes; книга рассматривается как дополнительный слой готовых и составных рифм. Наблюдения и ограничения зафиксированы в [DATA_SOURCES.md](DATA_SOURCES.md). Контейнеры Rhymes распакованы для исследования, но полный декодер записей ещё не создан.

До включения зафиксировать версии, происхождение, условия распространения, покрытие и качество каждого конкретного набора. Бесплатная загрузка Rhymes сама по себе не означает разрешение распространять его базу в нашем приложении. Полноту будущего словаря оцениваем после пробной сборки: отдельно число лемм, словоформ, вариантов ударения и покрытие контрольных текстов.

Сборщик данных работает отдельно от редактора: импорт → нормализация → объединение без потери омографов → слоги и фонетика → индексы → отчёт о покрытии и конфликтах → версия базы. Результат — SQLite-файл, включённый в установку. Пользовательские слова и поправки хранятся отдельно и переживают замену основной базы.

Поиск:

1. Получить варианты ударения опорного слова. При неоднозначности дать выбор; при неизвестном слове предложить поставить ударение вручную.
2. Построить звучание окончания от последней ударной гласной; для оценки богатства совпадения учитывать и предшествующие звуки.
3. Точные рифмы получать по индексу фонетического окончания. Близкие — из ограниченных групп по ударной гласной и структуре заударной части, затем оценивать фонетическое расстояние.
4. Применить фильтры и ранжирование: фонетическая близость, выбранные ритмические ограничения, частота. Показывать понятные признаки результата.
5. Возвращать результаты порциями. Поиск идёт в рабочем потоке; устаревшие ответы отбрасываются по версии запроса и документа.

Нормализация поиска допускает сопоставление е/ё, но исходное написание и произносительные варианты сохраняются. Фонетический модуль должен учитывать как минимум оглушение, мягкость и контекст произношения; буквенное совпадение не выдаётся за фонетическую точность. Качество оценивается на вручную проверенных парах, включая ложные совпадения.

**Стихотворный размер**

Поддержать пять основных моделей: ямб `∪ —`, хорей `— ∪`, дактиль `— ∪ ∪`, амфибрахий `∪ — ∪`, анапест `∪ ∪ —`. Здесь `∪` — слабая позиция, `—` — сильная. Отдельные состояния: «Авто», «Свободный/смешанный», «Недостаточно данных».

Анализ начинается с вариантов словарных ударений. Затем последовательности слогов сопоставляются с моделями с учётом пропусков метрического ударения, лишних ударений и окончаний строк. Результат объединяется на уровне строфы/секции. Для песен несовпадение с регулярной моделью не следует считать ошибкой текста.

Показывать лучший вариант, альтернативы и степень уверенности. Не подгонять неизвестные слова молча под желаемую модель. Предусмотреть исправление ударения отдельного слова и выбор размера/числа стоп для секции, с возможностью исключения для строки. Приоритет: настройка строки → секции → автоматический анализ. Возврат в «Авто» снимает соответствующее переопределение.

Переключение меняет ожидаемый ритм, подсветку отклонений и ранжирование рифм, но не переписывает текст. Для оценки замены анализируется вся будущая строка, а не только новое слово. Результат детектора проверяется на размеченном наборе стихов, песенных текстов и нерегулярных примеров; универсальную безошибочность не обещаем.

**Технологии и структура проекта**

Предлагаемый стек: Rust stable, egui/eframe, SQLite через rusqlite, serde/serde_json для проекта. Это локальное приложение целиком на Rust. [egui](https://github.com/emilk/egui) поддерживает настольные приложения; [TextEdit](https://docs.rs/egui/latest/egui/widgets/text_edit/struct.TextEdit.html) позволяет настроить отрисовку текста и получить диапазон курсора. Интерактивные окончания строк потребуют собственного слоя над редактором, поэтому сначала нужен небольшой прототип.

```text
poetrhymer/
  Cargo.toml                 # workspace
  crates/
    app/                     # окно, панели, команды, фоновые задания
      src/editor/            # TextEdit, подсветка, попадание клика в слово
      src/panels/            # секции, рифмы, метрика
      src/storage/           # файлы, автосохранение, восстановление
    core/                    # логика без зависимости от GUI и SQLite
      src/document/          # текст, строки, секции, диапазоны, правки
      src/linguistics/       # токены, слоги, ударения, фонетика
      src/rhyme/             # запрос, пары, фильтры, оценка кандидатов
      src/meter/             # модели, анализ, ручные настройки
    lexicon/                 # SQLite, индексы, пользовательские поправки
  tools/
    dictionary-builder/      # воспроизводимая сборка словарной базы
  assets/
    dictionaries/            # подготовленный словарь и его манифест
  tests/
    fixtures/                # примеры текстов, рифм, ударений и размеров
  docs/
    PLAN.md
    DATA_SOURCES.md           # создать при выборе источников
```

Принцип зависимостей: app использует core и lexicon; lexicon реализует интерфейс доступа к словарю, определённый в core. Сборщик использует общие правила нормализации/фонетики. Одна реализация правил обслуживает сборку и поиск.

Основные сущности: Document, Section, Stanza, Line, TokenSpan, WordForm, PronunciationVariant, RhymeQuery, RhymeCandidate, RhymeLink, MeterAnalysis, MeterOverride. В RhymeQuery раздельно хранятся диапазон замены и опорное слово/ссылка.

Диапазоны правок привязаны к ревизии текста. Перед заменой проверяются ревизия и исходное слово: результат старого запроса не должен менять другую строку после набора текста. UTF-8-байты, позиции символов редактора и графемы преобразуются явно; особые случаи — кириллица, ё, составные знаки ударения и дефисные слова. Стабильные идентификаторы строк и метаданные обновляются командами правки; при неоднозначном сопоставлении устаревшая привязка сбрасывается.

**Форматы и сохранность текста**

- Открытие и экспорт UTF-8 `.txt`: чистый текст с заголовками в скобках.
- Проект `.poetrhymer`: версионированный JSON с текстом, идентификаторами, ручными ударениями, схемами/связями рифм и настройками размера. Словарь в каждый проект не копируется.
- Обычное сохранение, автосохранение восстановления, предупреждение о несохранённых изменениях. Запись через временный файл с безопасной заменой; при сбое предыдущая версия остаётся доступной.
- Единая история undo/redo для набора и словарных замен. Программная замена не должна обходить историю редактора.

**Этапы и критерии готовности**

| Этап | Результат | Проверка завершения |
|---|---|---|
| 0. Проверка основы | Прототип редактора и небольшая пробная база | Клик по последнему слову, переносы, прокрутка, выделение, кириллица, замена и undo работают; подтверждены доступные поля и происхождение данных |
| 1. Обычный редактор | Набор, вставка, файлы, секции, восстановление | Исходный пример и текст с заголовками открываются/сохраняются без потерь; секции обновляются после правки |
| 2. Словарное ядро | Импорт, ударения, фонетика, точные и близкие кандидаты | Контрольные пары и омографы проверены; повторная сборка фиксированной версии воспроизводима; есть отчёт покрытия |
| 3. Основная функция | Панель, ручная опора, фильтры, предпросмотр, замена | Для «фуража» выбирается «спеша» из строки 2; кандидат заменяет только слово, сохраняет `».` и отменяется одним действием |
| 4. Большой словарь и выпуск MVP | Полная выбранная база, индексы, пакет Windows | Работа без сети, поиск не блокирует набор, результаты приходят порциями; проверены установка и восстановление после сбоя |
| 5. Помощник рифмовки | Предложения пар, схемы, ручное переопределение | Правильно обрабатываются AABB/ABAB/ABBA, непарные строки и исходный пример без ложной обязательной пары 1–3 |
| 6. Размер и ударения | Пять моделей, неопределённость, ручное управление | Размеченные примеры, неоднозначные ударения и смешанный ритм проверены; смена модели сразу меняет анализ и не меняет текст |
| 7. Доводка | Горячие клавиши, избранное, удобство и производительность | Полный пользовательский сценарий, длинный документ и реальный объём базы проверены на целевой машине |

Плановые ориентиры производительности, подлежащие измерению: обычный поиск первой страницы в прогретой базе — до 150 мс; обновление анализа после паузы в наборе — до 300 мс. Холодный запуск, размер установки и потребление памяти измеряются отдельно после выбора словаря. Это цели, а не результаты уже выполненных измерений.

Основные проверки ядра: разбор секций, сохранение текста, пунктуация, Unicode, неоднозначные ударения, фонетически похожие и ложные рифмы, отсутствие данных, ручные настройки. Интеграционные проверки: импорт базы, открытие/сохранение проекта, смена опоры, устаревший ответ поиска, замена и undo/redo, удаление связанной строки. Проверки интерфейса включают попадание в слово после прокрутки и визуального переноса.
